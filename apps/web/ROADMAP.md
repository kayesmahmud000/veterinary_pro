## Admin and Super Admin delivery roadmap

**Status: ADM-1 implemented locally; ADM-2–9 pending, 2026-10-13.** ADM IDs are web delivery slices under this roadmap, not a reset of completed backend sprint IDs. ADM-1 integrates existing role-review and administrative-access pages, preserving their URLs and behavior. Routes beyond ADM-1 remain proposed until their owning slice passes acceptance.

### Product outcome and dashboard structure

Provide one administration workspace at `/admin`, shared by ADMIN and SUPER_ADMIN, with permission-specific navigation and actions. Reuse the existing full-width shell, mobile drawer, sidebar account footer, language switcher and authenticated session boundary. Super Admin gets the administrative-access and platform-configuration controls through explicit permissions; there is no duplicate `/super-admin` application or role-switch control.

The overview at `/admin/dashboard` presents subscription activity, pending work and links into available modules. Begin with real subscription counts and recent professional applications; add financial trends, platform user/farm totals, triage workload and operational alerts as their contracts pass acceptance. Never compute platform totals from one page of results or display zero for a failed request. Metric cards declare their period, timezone and currency where relevant. The current metrics DTO has no currency field, so financial cards require the API-ADMIN-M contract decision first; count cards can ship independently.

Proposed sidebar groups:

| Group | Navigation destinations |
| --- | --- |
| Overview | Dashboard, Metrics and reports |
| People and farms | Users, Professional applications, Veterinarians, Farms |
| Catalog and content | Products/courses/eBooks/tools, Media, Public-site content |
| Commerce | Orders, Subscriptions, Plans, Payment follow-up |
| Veterinary operations | Triage, Consultations, Settlements, Review moderation |
| Platform | Notifications, Support, Audit log; Super Admin also gets Administrative access, Settings and System status |

Publish navigation entries only with working, authorized destinations. Planned modules remain in this roadmap rather than becoming dead links or simulated production pages. Global account Profile and Sign out remain at the sidebar bottom. Every module supplies bilingual loading/empty/error/denied/success states, URL-backed list filters and pagination, accessible confirmation where an action changes access, money or published content, and recoverable failures.

### Admin versus Super Admin permissions

These are roadmap defaults for new contracts; current backend permissions remain authoritative until a scoped change is implemented and verified.

| Capability | ADMIN | SUPER_ADMIN | Evidence or requirement |

| General account/farm support | Proposed scoped access | Proposed scoped access plus administrative-account governance | New APIs required; platform role does not create farm membership |
