# Web and mobile architecture

Client work uses the applicable [senior client engineer](../roles/frontend-ui.md) with [UI/UX Designer and UI Reviewer](../roles/ui-ux.md). Use the [UI workflow](../workflows/ui-change.md); the implementation facts below constrain design choices and must not be replaced by generic assumptions.

## Web: public site implemented; account and application UI pending

Updated 2026-10-07 after public-site interactivity. `apps/web/src/app/layout.tsx` owns the root document and global CSS. `(marketing)/layout.tsx` owns public navigation/footer; `(marketing)/page.tsx` and the farm-management, learning and veterinary-care routes render public product content. Root `not-found.tsx` provides 404 recovery. Shared marketing components use CSS Modules and Lucide. Server composition resolves localization and passes copy to small client components for navigation, goal selection, sample farm views/milk estimates, workflow/features and FAQ search. The landing hero uses a bilingual photo banner with autoplay and manual controls, backed by locally bundled Unsplash livestock photos; it does not fetch hero media from a third-party host at runtime.

**Confirmed from code:** `interactive-discovery.tsx` and `farm-demo.tsx` own local public-preview state. `src/lib/milk-projection.ts` parses Bangla/ASCII decimals and calculates 7/30-day constant-yield estimates. Demos use explicitly fictional animal/expense records and send/save no farm data; they are not the operational dashboard or browser offline implementation. See the [interactive public-site specification](../../docs/tasks/web-interactive-public-site/spec.md) and [verification plan](../../docs/tasks/web-interactive-public-site/plan.md).

**Confirmed from code (2026-10-07 hero/header):** `header-surface.tsx` owns pathname/scroll presentation while `site-header.tsx` keeps localized server composition. The homepage photo starts behind a fixed transparent header; after 16px of scroll the header becomes white, and returning to the top restores transparency. Other public routes use an opaque in-flow sticky header. Shared header-height tokens reserve hero and anchor clearance; the constrained hero container retains responsive gutters. The hero demo anchor uses Next.js Link so browser history restores the page and header together. See [hero/header spec](../../docs/tasks/web-hero-header/spec.md) and [verification](../../docs/tasks/web-hero-header/plan.md).

**Confirmed from code (2026-10-07 autoplay):** the hero cycles its three photos, supporting copy and CTA every six seconds. A localized Play/Pause control, hover/focus pauses, page/hero visibility checks and reduced-motion defaults govern rotation. Timer, media-query, visibility and intersection subscriptions are cleaned up on unmount. See [autoplay spec](../../docs/tasks/web-hero-autoplay/spec.md) and [verification](../../docs/tasks/web-hero-autoplay/plan.md).

**Confirmed from code:** `src/lib/i18n/` owns typed Bangla/English catalogs, locale validation and number formatting. `getLocalization()` resolves the request's `vetralink-locale` cookie with Bangla (`bn`) as the default, including invalid preferences. The root HTML language and generated metadata use that same locale. The selection action persists a validated preference and redirects to a validated local path/query. Existing public URLs are preserved; cookie-dependent pages render per request rather than as static exports. Separate indexable locale URLs/hreflang are not implemented. See the [localization spec](../../docs/tasks/web-localization/spec.md) and [verification plan](../../docs/tasks/web-localization/plan.md).

Public pages have no API dependency. There is no implemented auth/session flow, API client, global client store, dashboard, private feature navigation or browser offline storage. Do not infer operational farm tools from the public overview pages. Route inventory and implementation evidence live in [public-site spec](../../docs/features/web-public-site/spec.md) and [plan](../../docs/features/web-public-site/plan.md); the [web roadmap](../../apps/web/ROADMAP.md) owns progress.

Next.js App Router supplies routing, with strict TypeScript and `@/*` → `src/*`. The implementation uses global CSS tokens and scoped marketing styles; Tailwind is declared but not configured as the design system. For future account/data features specify session handling, cache isolation, API errors and tenant permissions before adding dependencies. Never treat client navigation as server authorization.

**Confirmed from code (2026-10-07 showcase):** `product-visuals.tsx` renders original sample product interfaces and SVG service artwork; `species-explorer.tsx` reveals planned animal-specific records. Server-rendered `resource-catalog.tsx` links three authored guides and filters `/learning?topic=records|milk|finances` with normal URL/history semantics. Fixed article pages share `guide-article.tsx`; a catalog-validated template route returns localized blank UTF-8 CSVs with private/no-store caching. These free public resources do not implement the paid catalog or account library. See [showcase spec](../../docs/tasks/web-product-showcase/spec.md) and [verification](../../docs/tasks/web-product-showcase/plan.md).

## Mobile: scaffold plus offline library

`apps/mobile/lib/main.dart` contains `VetralinkApp`, a Material 3 app using a teal seed and one text screen. `flutter_bloc` is declared but no feature BLoCs or navigation/auth flows are implemented. Do not invent an established state-management convention beyond this dependency and the architectural intent.

`lib/core/sync/` contains `OfflineDatabase`, `OfflineSyncEngine`, `SyncClient` and Dart sync DTOs. Dio performs HTTP calls, sqflite stores six domain tables plus queue/metadata. `SyncClient` defaults to localhost and accepts an injected Dio/base URL; production device configuration and secure session persistence still need design. The entry screen does not initialize or invoke this engine.

No Android/iOS platform projects are present at the inspected baseline, although mobile CI attempts an Android release build. The database imports `package:path/path.dart` without a direct `path` entry in `pubspec.yaml`; dependency hygiene should be verified during mobile work.

See [offline behavior](../features/offline-sync.md), [UI standards](../engineering/ui.md), and [testing](../engineering/testing.md) before implementing clients.
