# Administrative settlements and review moderation (ADM-6)

Date: 2026-10-16 (Asia/Dhaka). User selected ADM-6 settlements/moderation after ADM-5. Baseline: `4e1652a`, clean `dev-fontend` checkout. Status: implemented locally; acceptance evidence and deployment/provider limits are recorded in [plan.md](plan.md).

## Outcome and boundaries

ADMIN and SUPER_ADMIN can discover settlement ledgers, inspect per-currency filtered summaries and a veterinarian's ledger, review immutable fee splits, and confirm single/bulk local reconciliation with an external reference. They can discover reviews, inspect operational consultation/participant context and moderation history, and approve/flag/reject with a reason. Use current workspace/server/BFF/API identity protection, Bangla default plus English and Tailwind utilities. LEARNER/FARMER/VET/BUYER cannot enter the administrative routes. Existing participant/vet experiences retain separate permissions.

PAID means a local ledger record was reconciled by an operator; it is not evidence of an external transfer. Confirmation states this plainly. No gateway charge, refund, transfer, notification dispatch or clinical authorship is enabled. Reading any new or corrected legacy settlement endpoint must not create/update a ledger or audit. No schema migration is planned. No deployment, production write or Git history/index action is authorized.

Confirmed pre-implementation gaps: legacy consultation settlement GET invokes ledger creation; fee preview has missing-record/access/NaN handling gaps; legacy summary mixes currencies; payout save/audit and bulk operations are non-atomic; moderation changes/profile aggregates/audit are non-atomic; legacy vet review discovery accepts status filters and lacks an isPublic predicate. These touched boundaries must be corrected alongside the UI.

## Settlement contracts

Web: `/admin/settlements`, `/admin/settlements/[id]`, `/admin/settlements/vets/[vetId]`. List/search/filter/cursor paging; filtered per-currency summary; vet detail links; persisted detail/split/history; selection of up to 20 eligible rows for confirmed bulk reconciliation. Vet view uses the same list/summary APIs with a fixed vetId query; deny mismatched vet filters in the BFF/UI route composition.

API prefix `/api/v1/admin/settlements`, exact administrative roles and current-primary identity/version checks:

- GET `/`: strict `{limit:1..100 default20,cursor?:UUID,search?:trimmed max100,status?:PENDING|PROCESSING|PAID|HELD|REVERSED,vetId?:UUID,currency?:3 uppercase letters}`. Stable ascending ID keyset paging, `{items,nextCursor}`.
- GET `/summary`: same filters except limit/cursor; `{items:[{currency,count,totalGrossCents,platformFeeCents,vetEarningsCents,pendingPayoutCents,paidPayoutCents,heldPayoutCents,reversedPayoutCents}]}`. Group by currency/status with database aggregates, never load unbounded rows or add currencies. Pending includes PENDING/PROCESSING; held/reversed are separate. All money totals are nonnegative safe integer minor units. Summary is labeled filtered, not a global balance.
- GET `/:id`: repeatable-read detail snapshot; 404 absent record. GET `/:id/preview`: side-effect-free immutable fee-split preview `{id,totalFeeCents,platformFeeRate,platformFeeCents,vetPayoutCents,currency,matchesStoredSplit}`. Rate/amount are stored values, no custom-rate edit.
- POST `/:id/reconcile`: strict `{expectedRevision:64 lowercase hex,reason:trimmed5..1000,actorPassword:1..128,payoutReference:trimmed3..255,payoutBatchId?:trimmed1..100}`. Returns refreshed detail.
- POST `/bulk-reconcile`: strict `{items:[{id:UUID,expectedRevision}],vetId:UUID,currency,payoutReference,payoutBatchId?,reason,actorPassword}`; 1..20 unique IDs, one vet/currency. Entire batch commits or rolls back; one known audit event per changed ledger. Response `{items:detail[]}` max20. Repeat/stale submissions cause no second mutation/audit.

Shared exports in `validation/admin-settlements.ts`: `adminSettlementQuerySchema`, `adminSettlementSummaryQuerySchema`, `adminSettlementListSchema`, `adminSettlementSummarySchema`, `adminSettlementDetailSchema`, `adminSettlementPreviewSchema`, `adminSettlementReconcileSchema`, `adminSettlementBulkSchema`, `adminSettlementBulkResultSchema`; inferred types `AdminSettlementQuery`, `AdminSettlementRow`, `AdminSettlementDetail`, `AdminSettlementSummary`, `AdminSettlementReconcile`, `AdminSettlementBulk`.

Settlement row: `{id,consultationId,vet:{id,name}|null,status,totalFeeCents,platformFeeRate,platformFeeCents,vetPayoutCents,currency,processedAt:string|null,createdAt,updatedAt,revision,canReconcile:boolean}`. Detail extends row with `payoutReference:string|null,payoutBatchId:string|null,unavailableReason:null|STATUS|CONSULTATION_STATE|SNAPSHOT_MISMATCH,consultation:{id,status,paymentStatus,type,farmer:{id,name}|null,farm:{id,name}|null,feeCents,currency},history,historyTruncated`. History `{id,action,actor:{id,name}|null,reason:string|null,createdAt}` at most50 known settlement actions, no arbitrary metadata. Redact deleted identities; omit email/phone/provider IDs/raw ledger metadata/clinical content. List includes revision to bind batch confirmation to the displayed snapshot. Dates ISO strings; named currency/Asia/Dhaka rendering.

Reconciliation only PENDING/PROCESSING, with a COMPLETED/CAPTURED consultation, matching assigned vet/currency/fee snapshot, valid finite nonnegative integer amounts and exact split sum/rounded stored rate. HELD/REVERSED/PAID or inconsistent entries remain read-only with an honest reason. Reconciliation preserves immutable amounts/rate/currency, sets local PAID, reference/batch/processedAt, and audits atomically (`ADMIN_SETTLEMENT_RECONCILED`, `ADMIN_SETTLEMENT_BULK_RECONCILED`). Revision is SHA-256 of ledger ID/xmin plus related consultation xmin so eligibility changes invalidate confirmation.

Use existing password hasher/current-user repositories, fail-closed workflow limiter (10 attempts/900sec), transaction manager and audit repository. Re-lock/recheck actor password/version, related consultations and ledgers in deterministic order; revalidate eligibility/revision under locks and translate serialization/deadlock conflicts to 409 `SETTLEMENT_VERSION_CONFLICT`. Unavailable transition/inconsistent snapshot is 409 `SETTLEMENT_ACTION_UNAVAILABLE`; strict input422, denied/password403, missing404, rate429/unavailable503. Body cap32KiB (bulk is bounded20); single16KiB.

Legacy settlement GET uses an explicit read-only service/repository lookup and participant/admin authorization; absent consultation or settlement returns404. Fee preview requires participant/admin access, a real consultation and finite rate0..1; calculate with integer cents and the consultation currency. Preserve existing successful DTOs and existing internal capture-triggered creation. Harden legacy single/bulk processing to locked rechecks, partial mutable-field writes, valid references/eligibility, atomic audit and deterministic all-or-none/repeat-safe behavior, so those handlers cannot race/overwrite new reconciliation. Legacy single-currency summary contracts must reject mixed currency instead of labeling their combined total with one currency; new grouped summary supports mixed currencies correctly. No silent public-contract drift: document tightened validation and conflict behavior. UUID inputs are canonicalized to lowercase; casing aliases must preserve revisions and audit history. Omitting payoutBatchId retains an existing batch, and both response validation and audit describe that resulting value.

## Review moderation contracts

Web `/admin/reviews`, `/admin/reviews/[id]`: bounded searchable status/vet/rating filters, review detail/context, current privacy, moderation reason/history, confirmed action. Approval preserves the author's `isPublic` choice, rating, feedback and tags; it cannot publish a private review.

API `/api/v1/admin/reviews` GET strict `{limit:1..100 default20,cursor?:UUID,search?:trimmed max100,status?:PENDING|APPROVED|FLAGGED|REJECTED,vetId?:UUID,rating?:integer1..5}` with ascending ID pagination `{items,nextCursor}`; GET `/:id` repeatable-read detail; POST `/:id/moderate` strict `{status:APPROVED|FLAGGED|REJECTED,expectedRevision:64 lowercase hex,reason:trimmed5..1000,actorPassword:1..128}` and16KiB cap, returns detail. Same-status changes unavailable, no repeated audit. Errors `REVIEW_VERSION_CONFLICT`/`REVIEW_ACTION_UNAVAILABLE`409 plus identity/validation/limiter codes above.

Shared exports in `validation/admin-reviews.ts`: `adminReviewQuerySchema`, `adminReviewListSchema`, `adminReviewDetailSchema`, `adminReviewModerateSchema` and types `AdminReviewQuery`, `AdminReviewRow`, `AdminReviewDetail`, `AdminReviewModerate`.

Row `{id,consultationId,farmer:{id,name}|null,vet:{id,name}|null,rating,feedback:string|null,tags:string[],isPublic,moderationStatus,moderatedAt:string|null,createdAt,updatedAt}`. Detail extends row with `revision,moderationReason:string|null,moderator:{id,name}|null,allowedStatuses:(APPROVED|FLAGGED|REJECTED)[],consultation:{id,status,type,farm:{id,name}|null},history,historyTruncated`; history same safe shape as settlement, known review-submission/moderation events at most50. Privacy/redaction boundaries match settlement projections. Render feedback as text, never raw HTML; tag/status labels translated where known.

Password-confirmed fail-closed limits and current actor locked rechecks precede review/vet locks and xmin revision check. Same transaction updates moderation fields, recomputes APPROVED+isPublic vet rating/count with database aggregate, updates only existing profile rating fields, and writes `ADMIN_REVIEW_MODERATED` audit including bounded reason/status. Do not fabricate a vet availability profile when absent. Serialize all changed review writers for a vet through a shared user-row fence, including legacy submit/moderate, so public aggregates do not drift under concurrent reviews. Audit/profile failure rolls back moderation. Keep public review list forced to APPROVED+isPublic; unrelated callers cannot obtain private/nonapproved review by consultation ID. Participant/admin own-detail access remains. Preserve the author's review content and clinical records.
