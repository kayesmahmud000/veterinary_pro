# ADM-8 settings, diagnostics and reports

Selected 2026-10-19 by “go with next”, following ADM-7. Scope owns API-ADMIN-S/M/A in the [API register](../../../apps/api/ROADMAP.md) and ADM-8 in the [web sequence](../../../apps/web/ROADMAP.md).

## Required behavior

SUPER_ADMIN alone can open `/admin/settings`, `/admin/settings/integrations`, `/admin/system`, read typed configuration and save versioned report branding (Bangla/English organization names, optional support email (empty until configured) and default report timezone). Branding/contact appear on reports and their exports; timezone initializes reporting filters. No secret, environment, payment, clinical, entitlement or arbitrary infrastructure configuration is editable. Defaults apply without writing on GET. Saves require current identity, password, reason, confirmation, expected version, actor lock, serializable settings lock and same-transaction audit. Stale saves return SETTINGS_CONFLICT; uncertain writes require reload before another save.

System GET reports bounded live database/Redis probes and eight fixed BullMQ queues (waiting/active/delayed/failed/completed counts and worker registration count). Worker registration is evidence of registration, not successful job execution. Durable role-email pending/failed counts come separately from PostgreSQL. All errors are fixed status codes, never raw connection errors, URLs, job payloads or environment values. Integration status covers storage, email, Stripe, Daily, SMS/push and clinical notifications: MOCK / NOT_CONFIGURED / CONFIGURED_UNVERIFIED / SIMULATED / CREDENTIAL_CHAIN_UNVERIFIED. Daily/Stripe fallback and SES optional-SDK simulation are explicitly identified; S3 default-credential discovery remains unverified. Configuration is not connectivity/delivery. Only confirmed `RUN_DIAGNOSTICS` is exposed: read-only dependency probes, password/rate limiting, stable client request UUID, durable result and atomic audit. It cannot dispatch, retry, pause, delete or replay jobs. Repeating an ID returns the original actor's recorded result; an ID belonging to another actor is denied. External provider tests remain explicitly unavailable; this diagnostic checks database/Redis/queue metadata only.

ADMIN and SUPER_ADMIN can open `/admin/metrics` and `/admin/reports`. Reports use strict calendar `from` inclusive / `to` exclusive dates, timezone UTC or Asia/Dhaka, 1–366 days, no future end day beyond tomorrow. Return resolved instants and generation time. Snapshot totals/status/tier counts reflect current stored state at generation, excluding deleted accounts/farms, not reconstructed historical state. Range series count subscriptions created and orders created in each local month; order amounts grouped by stored currency and current status, with exact integer minor-unit strings. Completed-order totals are current COMPLETED state of orders created within the range, not cash receipts. No cross-currency total or FX conversion. Subscription rates use the existing ADM-4 USD local-plan contract: current ACTIVE subscriptions, monthly/annual interval inferred from period length using the existing calculator; label as estimated current list-price MRR, not invoiced revenue or historical MRR. No fabricated churn/LTV history. Empty aggregates are real zero/empty arrays, failures are errors. Aggregates run in a repeatable-read snapshot, server-side grouping, statement timeout, bounded grouping output; never collect all platform records in application memory.

Reports export the same aggregate schema as a versioned JSON artifact, with reason/confirmation, current authorization and an atomic export audit. Audit export uses ADM-2's exact role allowlist and metadata-only projection, half-open date range and optional actor/action/entity filters, at most 500 rows plus explicit truncation/next cursor; never raw snapshots, private notes, addresses, IPs or credentials. Each audit preparation is an independent snapshot; continuation does not freeze a multi-page snapshot across concurrent inserts. JSON avoids spreadsheet formula execution and preserves exact money. Exports require password and actor binding, are private/no-store, never cached or automatically downloaded on page load. The UI offers an explicit download link only after acknowledgement; clears artifacts when inputs/session change. ADMIN cannot export privileged events even with crafted filters. Every export is authorized by service plus HTTP guards and fixed BFF mappings.

## Contracts and recovery

New `/api/v1/admin/platform/settings` GET/POST, `integrations` GET, `system` GET, `diagnostics` POST are Super-only. `reports` GET, `reports/export` POST, `audit-export` POST allow both roles. Shared strict Zod schemas validate queries, bodies and projected responses; byte limits 16 KiB, export date/row bounds, fixed enums. `SETTINGS_CONFLICT` / `PASSWORD_CONFIRMATION_FAILED` / `AUTHORIZATION_CHANGED` / rate-limit/unavailable errors have explicit recovery. Current actor authorization version and primary role are checked in service and again under lock for writes; browser drafts cannot be submitted under a changed identity.

New additive tables `platform_settings` (singleton UUID, version and safe fields) and `platform_diagnostic_runs` (request UUID, actor UUID, bounded redacted JSON result/time). No existing rows or applied migrations change. Migration precedes code release; old code ignores new tables. Forward recovery preferred after writes; preserve backup and rehearse restore on disposable PostgreSQL. No production deployment/migration or real provider call is authorized by this slice.

## UXR-2 — Readable exact report currency (2026-10-22)

Display USD and BDT report totals as currency code plus ordinary major units, with exactly two fractional digits. This explicit policy covers the confirmed local USD plan and BDT/USD order examples; other stored three-letter codes retain exact localized integer values with an explicit minor-unit label, since the existing contract carries no denomination policy for them. Do not infer another currency's exponent or alter product pricing semantics. Group integers and localize digits/decimal separators in bn-BD/en-GB without converting any amount to JavaScript Number. Accept the existing unsigned 1–30 digit strings, including leading zeroes.

Use the same formatter for estimated MRR, order totals and monthly order totals on metrics/reports. Primary labels say Amount rather than integer minor units for converted values; preserve current-state, creation-cohort, list-price-estimate and provider limitations, separate currencies and unchanged exact raw JSON strings. No API/schema/storage, arithmetic, rounding, FX, payment/settlement or unrelated layout changes.

Acceptance: bn/en USD/BDT values 1234567 → 12,345.67 (localized), 1 → 0.01, 0 → 0.00, 9007199254740993 → 90,071,992,547,409.93; largest contract values and leading zeroes remain exact. Both admin roles at 320/1440px show readable totals without overflow on metrics/reports; JSON exports retain original strings. Unsupported codes remain truthful. Test malformed formatter inputs, existing report/security boundaries and UXR-1 regression.
