# Administrative consultation operations (ADM-5)

Date: 2026-10-16 (Asia/Dhaka). User instruction: proceed with the next planned ADM-5 batch. Status: implemented and verified locally; deployment/provider acceptance remains separate.

## Intended outcome

ADMIN and SUPER_ADMIN can review incoming cases, discover operational consultation history across every status, inspect request/participant/payment/assignment information, and confirm eligible manual/automatic assignments or reasoned cancellations. Reuse the current workspace, active-identity server protection, same-origin BFF, Tailwind utilities and Bangla-default/English localization. Other roles, including VET, cannot enter these administrative pages or endpoints; existing veterinarian/tenant experiences retain their separate permissions.

Confirmed pre-implementation baseline: existing triage APIs support queue/history filtering and candidate scoring, but assignment/cancellation save and audit separately, lack stale-state checks, and manual assignment does not enforce availability/capacity. Cancellation may update payment state before external hold release succeeds. Do not route the new administrative UI through those mutation paths.

## Routes and contracts

Web routes: `/admin/triage`, `/admin/triage/[id]`, `/admin/consultations`, `/admin/consultations/[id]`. Queue defaults to SUBMITTED; history defaults to all statuses. Both offer bounded search/status/type filters, cursor pagination, refresh and detail links. Lists/detail requests are read-only and never seed profiles, change payments/ledger or dispatch providers.

New API prefix `/api/v1/admin/consultations` with exact ADMIN/SUPER_ADMIN guards and current-primary identity/version checks. GET `/` accepts strict `{limit:1..100 default 20,cursor?:UUID,search?:trimmed max 100,status?:SUBMITTED|ASSIGNED|IN_PROGRESS|COMPLETED|CANCELLED,type?:ASYNC_TICKET|LIVE_VIDEO}`. List `{items,nextCursor}` has stable ID ascending cursor ordering. GET `/:id` returns a repeatable-read detail snapshot. GET `/:id/candidates` accepts no query and returns `{consultationId,items,truncated}` with at most 100 ranked candidates. POST `/:id/actions` accepts a strict discriminated action input with `action:ASSIGN|AUTO_ASSIGN|CANCEL`, `expectedRevision:64 lowercase hex`, `reason:5..1000 trimmed characters`, `actorPassword:1..128 characters`; ASSIGN additionally requires `vetId:UUID`. Assignment preserves an existing schedule; this slice does not create/reschedule appointments. Max action body 16 KiB.

Shared Zod projections define `adminConsultationQuerySchema`, `adminConsultationListSchema`, `adminConsultationDetailSchema`, `adminConsultationCandidatesSchema`, `adminConsultationActionSchema` and inferred types. Row fields: `id,status,type,chiefComplaint,farmer:{id,name}|null,vet:{id,name}|null,farm:{id,name}|null,animal:{id,name,tagNumber,species}|null,feeCents,currency,paymentStatus,scheduledAt,assignedAt,createdAt,updatedAt`. Dates are ISO strings or null. Deleted related identities are redacted. Detail adds `revision,allowedActions,history,historyTruncated,notifications,notificationsTruncated`. History entries `{id,action,actor:{id,name}|null,reason:string|null,createdAt}` include known operational audit actions only, never arbitrary audit JSON. Notification entries `{id,channel,status,dispatchedAt,readAt}` omit body/address/provider/error metadata. Both histories cap at 50 with explicit truncation. Candidate `{vetId,name,specialties:string[],isAvailable,currentActiveCases,maxActiveCases,totalScore,isEligible,ineligibilityReason:null|UNAVAILABLE|CAPACITY|SCHEDULE|PROFILE_REQUIRED}` excludes email/phone/private license details. Return only active, undeleted VET identities. Require an explicit availability profile before assignment; do not fabricate availability.

## Mutation correctness and provider boundaries

Use repository-owned Prisma queries and existing transaction/audit/user/password/limiter abstractions. Require password confirmation with a fail-closed workflow rate limit (10 attempts per 900 seconds), then re-lock/recheck actor eligibility/password/version, consultation and selected veterinarian. Opaque SHA-256 revisions incorporate consultation ID and PostgreSQL xmin, covering existing writers without a migration. Reject stale/repeated requests with HTTP 409 `CONSULTATION_VERSION_CONFLICT`; unavailable transition/vet/no candidate is 409 `CONSULTATION_ACTION_UNAVAILABLE`. 401 missing identity, 403 wrong role/password, 404 absent record, 422 invalid payload/query, 429 limit, 503 unavailable limiter.

Assign/reassign only SUBMITTED/ASSIGNED, never IN_PROGRESS/COMPLETED/CANCELLED. Recheck active VET role, availability, capacity (excluding this case on reassignment), existing live appointment working hours/timezone and +/-45 minute conflict. Rank using existing specialty/workload/availability weights, stable vet ID tie break. Auto-assignment selects the best currently eligible discovered candidate and rechecks under lock. Bound candidate discovery to 100 and expose truncation. Serialize competing new administrative assignments to the same veterinarian and use serializable isolation/retry or conflict translation to reject conflicting legacy writers rather than overwriting payment/clinical state. Update only assignment/status/timestamps, never a stale entity snapshot. Persist change and `CONSULTATION_ADMIN_ASSIGNED`/`CONSULTATION_ADMIN_AUTO_ASSIGNED`/`CONSULTATION_ADMIN_CANCELLED` audit together. Audit failure rolls back everything.

Cancellation is limited to SUBMITTED/ASSIGNED with payment UNPAID/FAILED/RELEASED and no provider payment reference. Cancellation is unavailable for AUTHORIZED/CAPTURED/provider-linked cases; assignment remains possible when clinical status permits. Ongoing/terminal care is read-only. Tell the operator when payment/clinical reconciliation is required. Preserve actual payment fields; do not claim a refund/released hold. Provider-driven cancellation needs a separately designed durable recovery contract.

Assignment records one durable IN_APP notification for the selected vet in the same transaction, visible through the existing vet notification feed. Cancellation records an IN_APP notice for an assigned vet if present. Explain that this is an in-app record, not proof of SMS/email/push delivery; no mock-bound external channel is dispatched. Existing notification histories are labeled stored outcomes, not verified provider delivery. No settlement, clinical note, prescription, chat, media signed URL, payment intent or encrypted phone access is added.

Compatibility refinement from source review: existing legacy `ConsultationRepository.save` must persist changed fields rather than replay a complete stale entity. Domain transitions check the persisted baseline and reject stale state. Legacy assignment shares a vet serialization fence and rechecks capacity/schedule in its save transaction, preventing mixed-isolation assignment races. Payment-only saves retain completed provider evidence while preserving newer assignment/cancellation fields; a hold already in flight when cancellation commits can still produce CANCELLED + AUTHORIZED requiring reconciliation. This slice does not promise to eliminate that external-provider race or automatically refund/release it. Candidate discovery evaluates at most the first 100 active vet IDs, then ranks that discovered set; automatic assignment chooses the best eligible veterinarian in that set. When truncated, disclose that additional veterinarians were not evaluated.

## UX and acceptance

Use named currencies/minor units and Asia/Dhaka date formatting. Show participant/farm/animal identity, request complaint, status/type/payment/schedule, safe operational history and notification history. Action form requires review/confirmation with case, vet and reason before save; password clears after submission. Prevent duplicate saves; retain nonsecret inputs after recoverable errors, provide explicit reload/review on stale state and bounded retry on request failure. No optimistic success before acknowledgement. Preserve session-change draft isolation and existing logout/role revocation handling. Navigation and return allowlists release only these routes.

Acceptance: strict contracts/queries, both admin roles and four denied roles at API/BFF/page boundaries, malformed and mismatched IDs, redaction, all-status discovery, empty/unavailable recovery, no-candidate/unavailable/full vet, assignment/reassignment/cancel, stale repeats/concurrent same-case and same-vet assignments, audit rollback, payment preservation/provider cancellation denial. Run focused API/BFF/navigation/style checks, shared/API/web compile/build, disposable PostgreSQL transaction tests if runnable, and controlled browser checks in bn/en at 320/1440px. Record unavailable real services and provider acceptance honestly. No production mutation/deployment or human-managed Git history writes are authorized by this implementation request.
