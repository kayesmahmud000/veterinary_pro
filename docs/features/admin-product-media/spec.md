## Outcome and baseline

ADMIN and SUPER_ADMIN manage product masters, draft/detail reads, edits, publication/unpublication, confirmed soft deletion, tracked multipart uploads, processing status/retry and verified asset attachment in Bangla and English. Reuse the full-width workspace and Tailwind primitives; require responsive/keyboard/loading/empty/error/conflict behavior and explicit currency/minor units and Dhaka dates.

Confirmed from code: public ProductsController GET routes do not authenticate optional tokens; legacy media routes accept arbitrary keys; VideoTranscodeProcessor writes stale full product snapshots. Protected read projections, persistent upload ownership and safe retry/inventory are absent. Existing product/media DTOs and task-3.1/3.2/3.3 specs remain compatibility references. Curriculum/progress/resources are API-B2, outside this batch.

## Design and alternatives

Use additive `admin/products` and `admin/media` contracts, not optional authentication on public routes. New AdminMediaUpload rows track product/uploader, generated private key, provider multipart ID, expected size/type, lifecycle and timestamps. Product.version supports optimistic edits; legacy repository writes increment it. Draft products may have empty contentS3Key; publication requires a real nonempty attached key. No placeholder files/paths. New managed transcodes produce isolated HLS outputs without mutating product masters; an explicit attachment action changes the product under version/row locks. This avoids stale worker overwrites. Reusing legacy routes without ownership or using only browser upload state were rejected because neither protects new assets or supports recovery.

## API and persistence contracts

All new routes require current active ADMIN/SUPER_ADMIN, strict shared Zod and fixed cookie BFF mappings; other roles and farm-header impersonation are denied. Lists use limit 1–100/default20, id>cursor keyset ordering, optional search/type/publication/productId filters as appropriate. Details expose only defined fields, not arbitrary product metadata or raw job errors. Public product metadata is restricted to descriptive fields; source keys, transcode errors and private metadata stay private.

Product GET list/detail includes version, title/slug/type/description, integer priceCents and nullable lower discountPriceCents, uppercase 3-letter currency, minimum tier, published flag, content key, timestamps. POST creates unpublished master with empty key. PATCH full editable details requires expectedVersion. POST :id/actions accepts PUBLISH|UNPUBLISH|DELETE, expectedVersion and reason 10–500. POST :id/asset takes uploadId and expectedVersion. Product type is immutable through editing; asset replacement requires unpublication. Writes recheck actor role/status/version under a user lock, lock product, compare version, increment it, and audit in the same transaction. Concurrent edits return 409 PRODUCT_VERSION_CONFLICT. Soft deletion retains orders/storage history. Legacy repository writes increment/check read versions; managed products and protected asset namespaces reject legacy mutation paths. A legacy product is claimed as managed atomically on its first new admin write/upload reservation. Managed worker output never replaces product data implicitly.

POST media/uploads takes a browser UUID requestId, productId, filename/contentType/fileSizeBytes. Categories derive from product type (MP4/WebM/MOV/MKV <=10GB; PDF/EPUB <=150MB; XLSX/XLS <=50MB). Bounds and extension/MIME pairing are validated before provider calls. Keys are server-generated under admin-assets/<productId>/<uploadId>.<extension>. Persist reservation/audit first, then call S3 outside transactions; matching completed initiation retries reuse the session, concurrent pending initiation returns UPLOAD_BUSY, mismatched request IDs fail. If a remote upload ID is known but persistence fails, cleanup attempts a provider abort; NoSuchUpload is accepted on abort recovery. A failed/abandoned initiation may be aborted and restarted with a new ID; provider lifecycle expiry must clean orphan multipart sessions if a process dies before its remote ID is saved.

GET media and media/uploads/:id list/detail show tracked uploads, product, owner ID, size/type, state, bounded progress and safe processing state. Inventory covers this managed namespace; existing product keys remain visible in product detail, not falsely presented as discovered bucket objects. Only uploader or SUPER_ADMIN can sign parts/complete/abort/retry. POST :id/part-url takes partNumber (1..ceil(size/10MB)); complete takes exact unique consecutive ETags for all parts. The service verifies S3 HEAD size/content type; a completed remote object is recognized on retry after a lost acknowledgment. Completion records UPLOADED; video processing is explicitly queued/retried with deterministic admin-transcode-<uploadId> job ID. Only failed jobs can retry; waiting/active/completed requests reuse the existing job. GET returns safe state/progress, not signed URLs or raw failures. Attachment validates session product/type and completed upload, and for videos a completed job plus canonical playlist key. Attachment never accepts a user-supplied storage key.

Legacy media part/complete/abort/manual-transcode/status paths reject managed admin-assets keys/jobs, preventing VET or arbitrary-key routes from bypassing session ownership. Existing legacy keys retain their contract. Managed processor output uses hls/<productId>/<uploadId>/master.m3u8 and skips all product mutation; explicit attachment owns publication readiness. Playback signs the attached playlist and scopes its cookies to that upload prefix, retaining valid existing root playlists for claimed legacy products. Published managed video content is a playlist, not a raw master.

## UI and recovery

Routes: /admin/products, /new, /[id], /[id]/edit; /admin/media and /uploads/[id] (upload session UUID, processing state shown there). Product actions require confirmation; stale changes reload details, retain clear feedback and do not silently repeat. Uploads use sequential 10MB direct PUTs with omitted credentials, HTTPS/configured-local HTTP URLs and exposed ETag. Failed parts retry in the same session; cancelling aborts. Completed uploads and processing survive reload through persisted inventory; interrupted uploads can be aborted/restarted. Re-selecting a matching local file allows retrying all parts safely. No raw browser file blobs or passwords are persisted. Bilingual messages cover provider/CORS failure and processing pending/failed/expired states without claiming provider delivery.

Meaningful API/repository/provider/worker and BFF tests cover role denial, metadata redaction, stale edits, atomic audit, wrong uploader/product/part bounds, MIME/size mismatch, lost-ack recovery, deterministic queue retry and private namespace protection. Controlled browser acceptance covers both roles/languages, new/edit/reload/publication/delete, uploads/failures/progress/attachment and responsive denial. Run shared/API/web builds, full API regression, web regression/style/browser checks and fresh review.

Additive migration: product.version NOT NULL default0 plus admin_media_uploads with UUID keys, restricted product/user FKs and bounded listing indexes. No destructive migration or data backfill; root Prisma tree is untouched. Disposable populated PostgreSQL migration rehearsal is complete; do not apply to configured live DB as part of this task. Apply migration before deploying code. Existing instances ignore the new table/version, so deploy migration first, upgrade/drain all API writers and workers, and only then expose the new web flows. Do not operate managed products through old server versions during rollout. Recovery disables new routes/navigation and retains records/objects/audit; no automatic object deletion. Retain the new API privacy/version safeguards; pre-ADM-3 API rollback after managed records exist requires a separately reviewed recovery plan. Real deployment PostgreSQL/Redis/S3/FFmpeg/CORS acceptance remains a release gate. No application dependency changes, Git integration or deployment authorized by this task.
