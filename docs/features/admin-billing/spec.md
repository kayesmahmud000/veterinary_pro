## API and persistence

New guarded `/api/v1/admin/billing/:kind` GET and `/:kind/:id` GET, where kind is orders/subscriptions/plans/dunning. Lists use strict bounded `limit` (1-100), UUID cursor, search (max 100), status filters and optional subscription ID for reminder history. Query fields/status enums are specific to the selected kind. Return `{items,nextCursor}` with explicit projections, ISO dates, named currencies/minor units and redacted deleted identities. Details include at most 50 items/history entries, with explicit truncation flags when additional records exist.

`POST /api/v1/admin/billing/subscriptions/:id/actions` accepts `{action:SCHEDULE_CANCELLATION|REVOKE_CANCELLATION,expectedRevision,reason,actorPassword}`. `PATCH /api/v1/admin/billing/plans/:id` accepts the editable plan fields plus expectedRevision/reason/actorPassword. Responses are the refreshed detail. Validate with shared strict Zod schemas, 16-KiB request limits, exact role gates and current primary identity/authorization version. Mutations require password verification and a bounded fail-closed workflow rate limit; re-lock/recheck actor eligibility/password and target row, reject stale revision/invalid transitions with HTTP 409, and commit domain change plus audit atomically. Retried stale requests cause no second write/audit.

Use an opaque SHA-256 revision derived from kind/ID/PostgreSQL xmin; detail data and xmin are read in one repeatable-read transaction. This detects all existing database writers without adding a version field that legacy writers would fail to increment. No schema migration or production financial fixture is required. Parameterize raw revision/locking SQL; allow table identifiers only from a fixed internal mapping. Extend operational audit visibility only for the new known actions. Closing the observed legacy cancel/reactivate cross-user authorization hole is required before release: HTTP handlers must pass the current actor and lifecycle service must verify ownership before updating.

Errors: 401 unauthenticated, 403 wrong/currently revoked role or bad password, 404 absent record, 409 BILLING_VERSION_CONFLICT/BILLING_ACTION_UNAVAILABLE, 422 invalid payload/query, 429 rate limit, 503 unavailable limiter/provider. Browser forms preserve non-secret draft/reason on failures, clear password after submission and require a confirmation dialog showing record, action and effect. Currency/date formatting uses locale and Asia/Dhaka. No raw environment variables or account credentials appear in logs/artifacts.
