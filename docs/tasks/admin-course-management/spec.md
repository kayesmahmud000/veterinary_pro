# Connected Admin and Super Admin Courses management

Date: 2026-10-23. Status: implemented and verified locally; production migration/deployment remain separate.
Owning feature: [YouTube courses](../../features/youtube-courses/spec.md). [Plan](plan.md).

## Scope and current evidence

The user requests list-first management, a connected three-step information/lessons/review wizard, direct edit/delete/publish/unpublish/details, actual enrollment counts, role-appropriate public actions/navigation, responsive/loading/media handling and preservation of learner behavior. Prepare a plan then implement without a second approval gate. Unrelated recovery, notification clarification and ROADMAP work remain paused. Preserve all pre-existing dirty work and human-managed Git policy; no deployment, production content mutation or migration is authorized.

**Confirmed from code:** `AdminCourses` in `admin-products.tsx` renders ProductForm before ProductList. Its create action routes to `AdminCourseCurriculum`; that editor routes to product details for publication. Generic protected `admin/products` already supports create, versioned PATCH, audited PUBLISH/UNPUBLISH/DELETE actions, and curriculum GET/PUT. Both current active ADMIN and SUPER_ADMIN are authorized; current identity/version is rechecked in the transaction. The existing dedicated course list filters to VIDEO_COURSE/YOUTUBE.

**Confirmed from code:** publication requires a valid free YouTube course with an ENROLLED lesson, or a ready internal HLS asset. Curriculum replacement requires unpublication, preserves retained lesson IDs, soft-deletes removed lessons and atomically increments product version/audit. Product information updates are permitted while published; the wizard must distinguish these rules. DELETE is already soft deletion plus unpublication, retaining lessons, media, enrollments and order relations; do not add cascading physical deletion or invent an enrollment restriction.

**Confirmed from code:** administrative Product DTOs omit thumbnail and enrollment/lesson counts. Product.metadata can hold additive validated course artwork without adding columns. Add explicit public-thumbnail URL projection and actual relation counts to the existing API, never expose arbitrary metadata or learner PII. Current image uploads only support video/documents/tools; a public thumbnail URL and existing public-demo fallback are supported without inventing an image-upload pipeline. Category has no supported course field and is omitted.

**Confirmed from code:** course enrollment is free and current-user scoped. YouTube create/publication rejects nonzero price; internal paid products have a different purchase/media path and no YouTube curriculum. User subsequently clarified they want paid private YouTube videos unlocked by enrollment. **Confirmed from provider documentation:** Private videos require individually invited YouTube accounts; Unlisted links can be reshared; YouTube API policies prohibit charging to watch embedded YouTube content. See [private access](https://support.google.com/youtube/answer/77272?hl=en), [privacy settings](https://support.google.com/youtube/answer/157177?hl=en), [provider policy](https://developers.google.com/youtube/terms/developer-policies). Paid hosting/access cannot be represented as functioning merely by changing a price field. The user resolved this: public videos and free enrollment now; permit paid pricing drafts using existing fields, with server-side publication/enrollment disabled until paid access is implemented.

## Required experience

- `/admin/courses` starts with a semantic course table (2026-10-23 user refinement), search/status filters, real counts, thumbnail/fallback, title, status/free label and useful dates. Add New Course opens `/admin/courses/new`. Columns show thumbnail/title/slug, publication, free/paid pricing, actual lesson and enrollment counts, updated date and existing actions. Keep a table at every size without horizontal scrolling. On narrower screens, place status/pricing/count/date information within the course cell and retain a separate actions column. Row actions display icons only, aligned fully right together with the actions heading, with localized accessible names and hover labels. View Details opens an accessible native modal with fresh product/curriculum evidence. Edit, publish/unpublish and soft delete are available directly without navigating to `/admin/products`.
- One wizard route retains course identity and in-memory information/lesson drafts across three steps. Step 1 validates existing master contracts (including slug conflicts), optionally accepts a validated public HTTPS thumbnail URL, and saves one draft before proceeding. Subsequent saves update the same ID. Preserve entered values on errors; uncertain create acknowledgement must not silently issue duplicate courses or claim success.
- Step 2 embeds the existing versioned lesson editor: titles/summaries/YouTube URLs, order, access, removal confirmation, save feedback, on-demand one-video preview with bounded failure/retry. Do not advertise file upload for YouTube links. Preserve existing internal uploader/ownership/progress behavior. Invalid/unsaved lessons block progression; an empty draft may be reviewed/saved but cannot publish.
- Step 3 shows saved master/curriculum, real count/access/thumbnail and obvious Save as Draft/Publish/Cancel. Publication, unpublication and deletion require existing reason/version confirmation, with course title visible. Buttons guard synchronous repeated clicks, use actor binding and disable interaction while authorization is uncertain. Acknowledgement errors retain intent and require explicit refresh on conflicts/uncertain state; never report success before API confirmation.
- Published master information can update under current backend rules without implicit status change. Lessons remain read-only until explicit confirmed unpublication inside the wizard. Explain temporary learner visibility/access effects; retained enrollment/lesson identities remain intact.
- Admin/Super public discovery/detail links lead to authorized course management, with no forced enrollment CTA or private-lesson learner playback bypass. Ordinary learners retain current flows. Existing exact middleware/BFF/API guards remain authoritative. Remove My courses from administrative navigation/account menu because the primary role is singular; retain its API/URL and data for existing personal memberships. Administrative roles retain management navigation.
- Course route loading provides clear shell/skeleton feedback while auth/data are checked, hides interaction/private previews during revalidation, and handles error/retry/empty states. The protected administration table and its loading state use the full workspace content width per the latest user correction; keep centered `w-11/12` on the wizard and public/learner screens. Bangla default and English, Tailwind-only styles, semantic controls, focus restoration, usable desktop/tablet/mobile and no overflow.
- Avoid per-card detail requests, hidden video previews and duplicate reads on step changes. List counts come from bounded API reads; modal detail loads only when opened. Preserve existing no-store/identity and shared session queue behavior. No new dependencies or speculative caches.

## Contract and regression boundaries

Extend existing shared `adminProduct*` schemas with optional nullable `thumbnailUrl` input/read, optional read-only `previewImageUrl`, lessonCount and enrollmentCount. Repository reads/mutation responses return actual relation counts; absent fields from older APIs display unavailable rather than fabricated zero. Store only the explicit thumbnail under metadata.courseThumbnailUrl. Preserve other metadata. Public Course thumbnailUrl resolves validated explicit artwork then public-demo artwork; restricted video sources remain absent. HTTPS only, bounded URL, no credentials; browser loads images directly with failure fallback, no server URL fetch/proxy. Generic product/media contracts remain compatible when the new optional field is omitted.

The wizard consumes existing product/curriculum/action endpoints and exact role guards. Add an exact `slug` filter (max200) to the guarded product list for bounded uncertain-create reconciliation, independent of mutable form values and paginated substring search. Add `/admin/courses/new` to the validated auth-return allowlist; keep unknown paths rejected. No enrollment details/PII endpoint is needed for the requested count. A new migration adjusts the existing YouTube CHECK constraint to permit nonnegative valid draft prices while requiring published YouTube courses to remain free. No columns/tables/data conversions are added; existing rows satisfy the new check unchanged.
