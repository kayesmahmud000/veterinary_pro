# Editable automatic course slugs

User request, clarified 2026-10-29: retain the slug input on admin course create/edit. Generate its default from the course title, allow manual editing, and do not require the administrator to satisfy separate slug-format validation. Once manually edited, later title changes must not overwrite that slug. Clearing it opts back into title-based generation; a blank slug at save uses the title.

Normalize submitted values into URL-safe lowercase slugs; support Bangla and English titles, short custom slugs, punctuation/spacing, and bounded lengths. Retain database uniqueness, current-role checks and optimistic versions. Retain the existing immutable submitted slug for uncertain create retries so a lost acknowledgement cannot create a second course. Existing custom slugs must not be overwritten just by opening/editing a different field; explicitly autogenerated slugs can follow title changes. Keep public course routes compatible with generated Unicode slugs. No schema migration, production writes or Git writes. Preserve pre-existing staged white-background changes.
