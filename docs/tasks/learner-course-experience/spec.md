## Investigation and root causes

**Confirmed from code:** `course-catalog.tsx` renders a wrapping form whose Field has no flexible width, and text-only two-column cards. Search already calls the validated API (100-character term, keyset pagination), but lacks result/clear feedback. `course-detail.tsx` gives only PUBLIC_DEMO lessons a button, so restricted rows have no interaction. `EnrollmentButton` always chooses firstLessonId and cannot preserve an explicitly selected lesson. CourseWatch supports direct enrollment but puts navigation below playback. Both learner routes inherit WorkspaceShell, including its sidebar and FarmContextProvider.

**Confirmed from code:** POST `me/courses/:id/enrollment` accepts exactly `{}`. Current active identity supplies userId; the route supplies productId. CourseEnrollment stores only those relations, ID and creation time, with user/product uniqueness. The service locks current user/product, reuses memberships and audits atomically. No extra name/phone/address/payment fields or migration are needed. Auth registration/login already collect required identity information. Enrollment remains an explicit action after login, never a GET/login side effect.

**Confirmed from code:** course responses have no artwork. Product has generic metadata but no supported thumbnail field or existing course image contract. Only CourseLesson has YouTube IDs; restricted IDs must remain private. Add an optional nullable `thumbnailUrl`, derived only from an explicitly PUBLIC_DEMO lesson, using a constrained YouTube image URL. No arbitrary metadata URLs, restricted-video imagery, new admin inputs, remote image proxy or database changes. This intentionally publishes artwork derived from an already-public demo; other outline fields remain source-free.

**Confirmed from code:** useCourseData already aborts obsolete reads and limits them to 14 seconds; private workspaceRequest is bounded and session-aware. YouTube loading already shares its script and limits readiness to 15 seconds, with error/retry/destruction. Keep those safeguards, improve reserved space and feedback, avoid recreating playback on locale/title-only changes, prevent late callbacks from clearing a timeout error, and remove failed frames. No blanket lazy-loading or speculative caching. Only selected demo/authorized lesson mounts a player. Actual runtime/visual observations will be recorded separately in the plan.

## Required behavior

- Navigation follow-up: Courses is the first public navigation item, followed by the other groups in their existing relative order. The shared list keeps desktop, mobile, footer and no-JavaScript navigation consistent in Bangla and English.
- All course screens and the learner header use the existing centered w-11/12 width, per the user’s explicit follow-up. A substantial full-width search panel contains a visible label, flexible input, search and clear controls. Search uses the actual API, handles rapid changes, pagination, empty/filter results, failure and retry. Applied state and count use localized numbers. No new search API.
- Responsive public catalog card grid: one column narrow, two tablet, four wide desktop (1280px+, per the 2026-10-30 follow-up), including matching loading-placeholder columns. The private course library retains its existing layout. Reserved 16:9 imagery, no broken image icons; loading placeholders, failure/missing fallback with course identity. Use native image loading: eager first visible image/detail, lazy remaining grid images; never preload videos. Links and focus states work with keyboard.
- Detail hero presents course artwork, title, description and real metadata without invented durations/instructors/ratings. Visible free enrollment/account confirmation. Curriculum shows accessible demos, locked lessons or enrolled access, each with a real action. Public demos play inline, scroll into view and can close; only one player exists.
- Selecting a locked lesson shows a clear enrollment panel naming that lesson and moves keyboard focus to it. Signed-out users sign in/register through existing auth with the exact protected lesson return. Signed-in users see account name/email and free enrollment confirmation; no invented fields. Pending state prevents repeated clicks. Errors retain intent and permit retry; uncertain acknowledgement remains safely idempotent. Success opens the selected lesson, updates membership state, and My courses reads authoritative server data. Continue is shown for existing membership.
- Learner routes retain exact URLs, middleware, metadata/noindex and WorkspaceGate identity boundaries. Move their pages to a dedicated route group with compact brand, language/account and Browse/My courses navigation, all centered at w-11/12. No dashboard sidebar/farm discovery. Other workspace/admin routes retain their existing layout.
- Player is primary with lesson title/summary, previous/next and course navigation. At >=1024px curriculum is to its right, in a bounded scrollable panel; below that it follows the player. Current lesson uses aria-current and a visible label. No forced autoplay or automatic advancement. Course outline persists across same-course client lesson navigation without redundant course reads.
- Image frames reserve dimensions; fallback is localized and decorative artwork has empty alt beside existing titles. Video frame retains at least 200px height and width, including 320px viewport. Initialization has visible bounded feedback; player/API failure has explanatory retry, and another lesson remains selectable. Switching or leaving destroys old player. Locale/title changes should not reload video; iframe title remains descriptive.
- All authored styling uses Tailwind utilities; existing tokens/primitives and Bangla-default/English copy. No dependency upgrade, authored CSS, inline styles, unrelated refactor or ROADMAP edit.

## Risks, compatibility and recovery

Do not broaden enrollment or playback authorization. Route-group movement must retain middleware protection and auth return allowlists; test source scanners that formerly assumed workspace paths. Account/version transitions must discard private course state. Preserve admin preview usage of YouTubePlayer. Native external thumbnails disclose image requests to YouTube; no requests when no public artwork exists, no video frames until requested, no arbitrary image origins. Returning to earlier source needs no database rollback; revert only this task's application edits and keep membership/audit data.
