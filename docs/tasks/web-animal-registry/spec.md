# Web animal registry — first operational slice

Approved by the post-login workspace plan, Task 6. Scope: tenant-scoped list/search/species/status pagination, registration and detail with basic edit. Preserve API animal contracts, audits and quota guards. Pedigree editing, weight histories, tags, imports and archiving remain separate.

Confirmed from current source: `animals.controller.ts` GET/POST/PATCH permits OWNER, MANAGER, HERDSMAN and VET_STAFF with TenantGuard; POST additionally checks ANIMALS quota. Primary account role never substitutes for membership. The BFF must allow only UUID-selected animal routes, cookie authorization and shared enum values; reject owner/farm/audit/metadata injection and unknown keys. Responses must belong to the selected farm.

Registration requires a trimmed 1–50 character tag, species and gender; optional name/breed/RFID use API lengths 100/100/50. DOB is a real YYYY-MM-DD date no later than the current UTC business date; weight is kilograms 0.01–9999.99, with up to two decimal places. Initial status ACTIVE is explicit. Optional blanks are omitted; edit blanks clear nullable fields. API alone owns tag normalization, uniqueness within a farm, audit and quota. Two farms can use the same tag.

Write controls require successful access status with canWrite=true and, for registration/member addition, quota canAccommodate=true. Failed access/quota reads never enable write controls. Read-only and quota feedback is localized and recoverable; no billing route is invented. Missing subscription blocks writes. Form values remain on API validation/conflict/timeouts, focus errors and prevent duplicate submit with a ref guard. Basic edits send only changed fields; nullable clearing is explicit, so unrelated snapshot fields are not overwritten. On timeout users inspect/search the registry before retrying because the animal API has no idempotency key. Dirty farm switching, ordinary links and browser history require explicit discard; confirmed animal/farm changes remount form state. Same-account session revalidation hides interaction while preserving typed drafts.

URLs retain page, search, species and status filters using normal GET forms/links, so Back restores the query. List uses server meta.total/pageSize/totalPages; no client synthetic counts. Detail identifiers are UUIDs and the API must return matching id and farmId. Units, local dates and status labels are bilingual. Loading, empty, denied, malformed and network errors render distinct feedback and retry. Exactly one main/H1 and no horizontal overflow at 320px.

Acceptance: strict body/query and cross-tenant response tests; browser create/read/edit/error preservation, duplicate-submit protection, filter/history and quota denial in bn/en with controlled fixture. Also attempt the existing isolated PostgreSQL/Redis/API runbook; unavailable infrastructure is recorded and never reported as passing.
